# テクニカルサポート業務日報システム

業務委託メンバーが日報を入力し、Google スプレッドシートにデータを蓄積。指定日のデータを別紙6様式のPDFとして出力するシステム。

## 構成

| ファイル | 内容 | 配置場所 |
|---|---|---|
| `index.html` | 日報入力フォーム | GitHub Pages で公開 |
| `gas_code.js` | doPost: フォーム→スプレッドシート | 閲覧用スプレッドシート（CCBT業務完了報告 2026）の Apps Script |
| `gas_code_admin.js` | PDF生成 + 割り振り台帳の管理 | 管理用スプレッドシート（CCBTテクニカル業務 実績管理 2026）の Apps Script |
| `日報ヘッダー.csv` | スプレッドシートのヘッダー行 | — |

## フォーム URL

https://itoyuya.github.io/daily-report2026/

## セットアップ手順

### 1. Google スプレッドシート

1. 新規スプレッドシートを作成
2. `日報ヘッダー.csv` をインポート
3. シート名を「日報」に変更

### 2. Google Apps Script

1. スプレッドシートの「拡張機能 → Apps Script」を開く
2. `gas_code.js` の内容を貼り付け
3. `CONFIG` の `DRIVE_FOLDER_ID` を保存先フォルダのIDに設定
4. デプロイ → ウェブアプリ（実行: 自分、アクセス: 全員）
5. 発行されたURLを `index.html` の `GAS_URL` に設定して push

### 3. PDF 生成

管理用スプレッドシート（CCBTテクニカル業務 実績管理 2026）のメニューから実行する。

#### 設定シート（用途別に2枚）

| シート | セル | 用途 | 使う機能 |
|---|---|---|---|
| **設定_日報** | B3 | 対象日 (`YYYY-MM-DD`) or 対象月 (`YYYY-MM`) | 日次PDF |
| **設定_請求集計** | B3 | 対象月 (`YYYY-MM`) | 請求集計シート / 請求サマリPDF |
| | B5 | L 前月繰越H | 同上 |
| | B6 | S 前月繰越H | 同上 |

初回はメニュー「**設定 → 設定シートを準備/再構築**」で両シート生成。旧「設定」シートが残っている場合は値をベストエフォートで移植する（旧シートは削除されないので手動で削除）。

#### 日次PDF（メニュー: 日報PDF → 日次PDF出力）
- `設定_日報` シート **B3** に `YYYY-MM-DD`（指定日）または `YYYY-MM`（その月の全日分）を入力
- 出力: `業務日報_YYYY-MM-DD.pdf`
- テンプレート: `テンプレート_日報` シート

##### 氏名の表示マッピング（PDF表示専用）
契約関係書類は正式表記で記載する経理依頼への対応として、**日報PDFに書き出す氏名だけ**を正式表記へ置換する。フォーム送信値・スプレッドシートの値・各種数式/関数は**カタカナのまま**運用する（数式が氏名キーに依存しているため、データ側は変更しない）。

- 定義: `gas_code_admin.js` の `PDF_DISPLAY_NAME_MAP`（例: `'イトウ' → '伊藤'`）と `displayName_()`
- 適用箇所: 日次PDFのシフト行（`{{shift}}`）と、複数人日のときの `【氏名】` プレフィックス（`{{tasks}}` / `{{content}}` / `{{notes}}`）
- マッピングに無い氏名はそのまま表示する
- 月による出し分けはしない（過去月のPDFを再生成しても正式表記になる）

#### 請求項目別 月次サマリPDF（メニュー: 割り振り → 請求項目別 月次サマリPDF出力（クライアント送付用））
- `設定_請求集計` シート **B3**=`YYYY-MM`、**B5**=L繰越H（前月）、**B6**=S繰越H（前月）を入力
- 出力: `請求サマリ_YYYY-MM.pdf`
- テンプレート: `テンプレート_請求サマリ` シート（事前に作成必須）
- **用途**: CCBTへ送付するサマリー。4項目別の **延べ日数・延べ人数・金額** を表示する想定。L/Sポスト区分は外す方針

##### 集計仕様（L/S別の繰越方式）
「業務時間/8h=1ポスト」社内ルールに整合。1日が8時間を超える業務が多発するため、月単位で時間を集計→ポスト換算→端数は次月へ繰越、で精算する。

1. **当月実働H** = 割り振り台帳の L〜O 列を月で集計（L/S別）
2. **使用可能H** = 当月実働H + 前月繰越H（`設定_請求集計` B5/B6 より）
3. **みなしP** = `floor(使用可能H / 8)`（整数ポストに切り下げ）
4. **翌月繰越H** = 使用可能H − みなしP × 8（次月の `設定_請求集計` B5/B6 に転記する）
5. **項目別配賦**: 各項目への金額按分は、みなしP を **当月実働の項目別時間比** で割り振り
6. **金額**: みなしP_L × 36,000 + みなしP_S × 29,400 → +消費税(10%) = 税込合計

##### プレースホルダ（テンプレート側で使う分だけ配置すればよい）
- 共通: `{{year_month}}`, `{{responsible}}`
- L/S精算: `{{hours_l/s}}`, `{{carry_in_l/s}}`, `{{avail_l/s}}`, `{{deemed_l/s}}`, `{{carry_out_l/s}}`
- 項目別 時間: `{{item1_total}}`〜`{{item4_total}}`, `{{itemN_hours_l}}`, `{{itemN_hours_s}}`, `{{grand_total}}`
- 項目別 延べ日数・延べ人数: `{{itemN_days}}`, `{{itemN_persons}}`, `{{total_days}}`, `{{total_persons}}`
- 項目別 按分P・金額: `{{itemN_posts_l}}`, `{{itemN_posts_s}}`, `{{itemN_posts}}`, `{{total_posts}}`, `{{itemN_amount}}`
- 集計金額: `{{subtotal_amount}}`, `{{tax_amount}}`, `{{grand_amount}}`

#### 請求集計シート（メニュー: 割り振り → 請求集計シートを更新（社内確認用））
- `設定_請求集計` シート **B3**=`YYYY-MM`、**B5**=L繰越H（前月）、**B6**=S繰越H（前月）→ メニュー実行
- 出力: `請求集計` シート（既存なら上書き）
- **用途**: 請求書本体は別途社内フォーマットで作成するため、その「数字の根拠」をスプレッドシートに表示しておくシート

##### 表示構成

**L/S別 ポスト精算**

| 区分 | 当月実働H | 前月繰越H | 使用可能H | みなしP | 翌月繰越H | 単価(円) | 金額(円) |
|---|---|---|---|---|---|---|---|
| L | … | … | … | (整数) | … | 36,000 | … |
| S | … | … | … | (整数) | … | 29,400 | … |
| | | | | 税抜小計 | … |
| | | | | 消費税(10%) | … |
| | | | | 税込合計 | … |

**翌月繰越** （★この値を次月の `設定_請求集計` B5/B6 に転記）

**項目別 内訳（みなしPを当月実働時間比で按分）**

| 項目 | L時間(h) | L按分P | S時間(h) | S按分P | 金額計(円) | 延べ日数 | 延べ人数 |
|---|---|---|---|---|---|---|---|
| ①実施計画策定・全体管理 | … |
| ②機器運用 | … |
| ③設営管理・技術支援 | … |
| ④各事業におけるテクニカルマネジメント | … |

請求書を社内フォーマットで作成する際は、この `税込合計` または項目別 `金額計` を転記する。

##### 算出ロジック
1. 割り振り台帳の月内行から、L/S別×項目別の時間を集計
2. L/S別に: 当月実働H + 前月繰越H = 使用可能H → `floor(/8)` = みなしP → 余りが翌月繰越H
3. 項目別: みなしP_post × (item_post_hours / total_post_hours) で配賦
4. 金額: みなしP_L × 36,000 + みなしP_S × 29,400 → +消費税(10%)

### 4. 4請求項目への割り振り（割り振り台帳）

請求書の4項目（実施計画策定・全体管理／機器運用／設営管理・技術支援／各事業におけるテクニカルマネジメント）に各日報を時間配分するためのワークフロー。**arsaffix内部のみで運用**。業務従事者は関与しない。

#### 使い方
1. 管理用スプレッドシートのメニュー「**割り振り → 業務完了報告より最新データを読み込み**」を実行 → 「割り振り台帳」シートが自動生成され、最新の日報が追加される（増分のみ、重複なし）
2. 必要に応じて「**割り振り → 自動取り込みをON**」を実行 → 以降シートを開くたびに自動で取り込み（installable trigger）
3. 「割り振り台帳」シートの L〜O 列（4項目）に時間（h、0.25刻み）を入力
4. P列（配分計）= L+M+N+O、Q列（差異）= 勤務時間-配分計 が自動計算
5. 差異が0以外、または S ポストで項目1/4 に値が入った場合はセルが赤くなる（要修正）
6. 月末:
   - 社内確認用に「**割り振り → 請求集計シートを更新（社内確認用）**」で `請求集計` シートを更新（L/S別ポスト数・金額の明細）。請求書はここの数字を社内フォーマットに転記して作成
   - クライアント送付用に「**割り振り → 請求項目別 月次サマリPDF出力（クライアント送付用）**」で `請求サマリ_YYYY-MM.pdf` を生成

#### 列構成（割り振り台帳シート）

| 列 | 内容 | 入力 |
|---|---|---|
| A | タイムスタンプ（重複排除キー） | 自動 |
| B | 日付 | 自動 |
| C | 氏名 | 自動 |
| D | ポスト（L/S） | 自動 |
| E〜F | 開始 / 終了 | 自動 |
| G | 勤務時間 (h) | 自動 |
| H | イベント | 自動 |
| I | 実施事項 | 自動 |
| J | 業務内容 | 自動 |
| K | 特記事項 | 自動 |
| **L** | **①実施計画 (h)** ※L のみ | **手入力** |
| **M** | **②機器運用 (h)** ※L+S | **手入力** |
| **N** | **③設営・技術支援 (h)** ※L+S | **手入力** |
| **O** | **④事業マネジメント (h)** ※L のみ | **手入力** |
| P | 配分計 (=L+M+N+O) | 数式 |
| Q | 差異 (=G-P) | 数式（0以外で赤） |
| R | メモ | 任意 |

#### 制約バリデーション
- **差異≠0** → Q列が赤（時間配分が勤務時間と一致していない）
- **S ポスト × 項目1（L列）** → 該当セル赤（サポーターは①計上不可）
- **S ポスト × 項目4（O列）** → 該当セル赤（サポーターは④計上不可）

## スプレッドシートのカラム構成（日報_2026）

| A | B | C | D | E | F | G | H | I | J | K | L | M |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| タイムスタンプ | 日付 | 氏名 | ポスト区分 | 開始時間 | 終了時間 | イベント名／実施業務 | 実施事項 | 業務内容 | 特記事項等 | 気づき・振り返り | 勤務時間 | 勤務形態 |

- D列（ポスト区分）は L（リーダー）/ S（サポーター）
- G〜J列の内容はPDF（別紙6）に出力される
- K列（気づき・振り返り）はarsaffix内部用でPDFには含まれない
- L列（勤務時間）は開始・終了時間から自動算出（単位: 時間）
- **M列（勤務形態）は `現地`（交通費あり）/ `リモート`（交通費なし）**。arsaffix内部の報酬・交通費把握用で、CCBT提出物には出さない。PDF生成・割り振り台帳・請求集計はいずれも列0〜11の位置参照で、M列は読まないため既存処理に影響しない（末尾追加のみ）

## 日跨ぎ勤務の扱い

終了時刻が開始時刻より前の場合（例: `22:00`〜`01:00`）は日跨ぎとみなし、24時間を足して勤務時間を算出する。

- **1件の日報 = 開始日の1行**として記録する。日付欄には**業務を開始した日**を入力する
- 日次PDF（別紙6）には**開始日の分にのみ**出力される。翌日側のPDFには 00:00〜終了時刻の部分は現れない
- 請求集計でも開始日の属する月に全時間が計上される（Cルールで 1行 = 1ポスト）
- 表示は日跨ぎのとき終了時刻に「翌」を前置する（`22:00〜翌01:00`）。25時間表記は使わない
  - 日次PDFのシフト行（`gas_code_admin.js` の `isOvernight_()`）
  - 割り振り台帳 F列（`formatEndTimeForDisplay_()`）
  - フォームの確認画面（`index.html` の `calcDuration()`）
- **勤務時間が16時間を超える入力はフォームでブロックする**（`MAX_WORK_MINUTES`）。開始と終了を取り違えたときに日跨ぎ扱いで巨大な勤務時間が通ってしまうのを防ぐため。16時間ちょうどまでは送信できる

## 日報を訂正したときの反映

日報シートのL列（勤務時間）は**数式ではなく値**である。doPost がフォーム送信時に一度だけ計算して書き込む。
そのため、あとから開始・終了を直しても勤務時間は自動では変わらない。訂正が請求に届くよう、次の2段構えで反映する。

### 1. 日報シート側（`gas_code.js`）

- メニュー「**日報メンテナンス → 時刻編集時の勤務時間 自動再計算をON**」を一度実行しておく（installable な onEdit トリガー）。以降、E列（開始）・F列（終了）を編集するとその行のL列が自動で計算し直される
- 過去分をまとめて直すときは「**日報メンテナンス → 勤務時間を一括で再計算**」。書き換える行の一覧を確認ダイアログに出してから適用する。開始・終了が読み取れない行は触らない
- 算出は `calcWorkHours_()` に一本化してある（doPost・onEdit・一括再計算がすべて同じ規則。日跨ぎ対応込み）

### 2. 割り振り台帳側（`gas_code_admin.js`）

「割り振り → 業務完了報告より最新データを読み込み」は**新規追加に加えて、取り込み済みの行の A〜K列を日報側の現在値で上書き**する。

- **L〜O列（4項目の配分）と R列（メモ）は必ず保持する**。上書きするのは日報から来る A〜K列のみ
- 勤務時間（G列）が変わった行は差異（Q列）が赤くなる。配分を入れ直す必要があるというサイン
- 行の同一性はタイムスタンプで判定する。次の行は上書きの対象外とし、実行時のアラートで一覧を出す
  - **タイムスタンプが空の行** — 台帳に取り込まれない。請求から漏れるので日報シート側の修正が必要
  - **タイムスタンプが他の行と重複している行** — どの行か特定できないため上書きしない（貼り付けで作られた行に起きる）
  - **日付が日付型でない行**（例: `8月7日（金）` という文字列）— 日次PDFの対象日に一致せずPDFに出ない
  - **勤務時間が開始・終了と合わない行** — 日報側で一括再計算を促す

### シートに直接行を打ち込まない

タイムスタンプのない行・日付が文字列の行は上記の通り請求とPDFの両方から抜け落ちる。代筆もフォームから送信する（特記事項に「代筆：〇〇」と書く運用が既にある）。
